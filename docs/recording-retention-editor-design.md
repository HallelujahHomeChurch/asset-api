# 錄影動態保留期限與後台編輯體驗

日期：2026-10-05（Asia/Taipei）
狀態：使用者已同意設計並要求 PR／merge；實作計劃已補齊待審閱，尚未實作或套用正式資料。

## 使用者需求

後台可調整全體錄影保留天數，預設 30 天，不需再次發布程式。適用尚未進入不可逆清理的既有與新影片，與發布／草稿狀態無關。刪除重用現有工作與 R2／Blob 生命週期，不新增服務、容器或掃毒流程。

編輯頁移除觀看資格說明及固定 30 天說明；標題提示為「最多 180 字」。下架按鈕移至「影片資訊」標題同排右側，仍為取消發布，保留確認 dialog；刪除按鈕及其語意不變。

封面不再提供與第一張自動封面選項重複的「恢復自動封面」按鈕。裁切確認後立即出現自訂封面項目，顯示本機預覽、spinner 與上傳／處理狀態；成功後成為待儲存選擇，儲存成功才取代正式封面。失敗保留目前有效封面，顯示錯誤與重新上傳入口。既有自動封面仍可直接點選。

## 保留政策與權限

- 在 Admin 影音清單提供「保留設定」，不加入需另外發布的網站導覽設定。
- 推薦有效範圍 1–365 整數天，預設 30；不提供 0、無限期、每支覆寫或依發布狀態例外。
- Asset 持久化單一錄影保留政策與 revision，作為媒體生命週期權威。CMS 負責管理入口、權限及內容投影；不建立兩份可獨立修改的政策。
- 修改僅限具有 `cms:recordings:write` 的真人管理員；CLI／Service Principal 不取得全域清理政策修改能力。
- 讀取、預覽、更新皆經 Gateway → CMS → Asset 既有可信服務邊界。更新以 revision 防止覆寫，具冪等性與持久稽核；稽核失敗不套用。
- 縮短天數前預覽受影響筆數與估算容量，顯示不可復原警告並確認。預覽綁定 proposedDays、政策 revision 與伺服器計算時間；過期或政策衝突要求重讀。筆數是預览時間點的估計，正式執行按每支影片當時狀態重新判斷。

## 時間語意

`effectiveExpiresAt = uploadedAt + retentionDays × 24 小時`，以 UTC 時間點比較，不依瀏覽器時鐘或曆日午夜。

- CLI：伺服器接受完整 HLS 上傳完成命令時的 `completed_at`。
- 瀏覽器：伺服器接受原始檔案完成命令時的 `completed_at`，沿用至轉出的 HLS 套件；不從轉檔結束重新計時。
- 起算時間一旦確認不可因 resume、重試、編輯、封面變更、發布或取消發布而重設。
- 已有影片從原始 completed_at 回填／投影，不使用目前誤代表 ready_at 的 CMS uploadedAt。遇到缺失或不一致先列出異常，不以「今天」填值。
- 尚未上傳完成的 session 保持既有上傳逾時；Blob 來源暫存及失敗重試期限不因本設定延長。

## 動態生效與不可逆邊界

- 設定儲存後，新的清單、封面存取、發布及播放憑證核發讀取最新政策；不得繼續把既有 expires_at 或 ready_at＋30 天當最終權威。
- CMS 清單、日期、排序／分頁及前台「最近 30 天」文案一起改為與政策一致；不要讓舊期限篩選先把延長後仍有效的影片排除。前台可用不寫死天數的「最近錄影」。
- 政策不可取得時，不使用預設 30 天繼續核發新憑證或做破壞性清理。
- 已簽發的 Worker 播放憑證無法單靠修改資料庫立即撤回，最長仍可存活一小時。新憑證立即採新期限；到期檔案至少保留至既有有效憑證安全結束，不承諾立即踢出正在觀看的會員。
- 背景清理與政策更新使用一致的鎖定順序。進入不可逆刪除前重新讀政策／revision並持久化刪除狀態；不能依舊候選清單刪檔。
- 調長政策只延長尚未進入不可逆清理的影片；已刪除或已開始清理者不復活。UI 預覽應明示此界線。
- 清理沿用既有 fenced job、tombstone、重試、限定物件路徑及晚到寫入補掃，涵蓋 HLS、封面、時間軸圖。沒有新增全 bucket 刪除。
- 錄影媒體保留天數與會員追溯紀錄 365 天分開；不變更 DSR、稽核或追溯紀錄保存期限。

## 契約與相容性

涉及 Asset（政策、完成時間、授權與清理）、CMS（管理 API、同步／清單／發布）、Gateway（精確管理路由）、SDK（canonical OpenAPI）、Admin（設定及封面狀態）、Web（列表文案）；Audit catalog 納入政策變更事件。不要求 CLI 新參數或操作流程。

Asset／CMS 的完成時間與政策相關欄位採 additive contract，先發布相容 producer，再更新 consumer。動態政策啟用前必須移除 CMS 固定 720 小時驗證，並完成既有資料 dry-run；不得在 consumer 尚未相容時改正式期限。

保留目前 PR／worktree，完成擴充後重新測試、review 與更新 PR。正式隱私告知補充仍是獨立待核准項，不視本次「請處理」為其授權。

## 驗證與啟用門檻

1. 30→14 天與 30→60 天同時覆蓋 CLI／瀏覽器、已發布／草稿、既有影片、正在處理與已刪除影片。
2. 修改政策和 cleanup 同時發生、失敗重試、授權核發跨服務往返中政策縮短，皆不依過期狀態誤刪／超期核發。
3. 原始 completed_at 保持不變；重傳同一操作、重新發布、封面上傳不延長期限。
4. 清單分頁、封面、字幕／預覽若有、畫質清單、播放與 R2 清理遵循同一有效期限；既有憑證緩衝明確驗證。
5. 封面慢速 PUT、pending／processing、失敗、完成、切換影片與卸載具 UI 測試；spinner 有可存取狀態，釋放本機 Object URL，避免舊回應污染新影片。
6. 各 repo canonical contract／測試／CI 通過，再按相依順序合併發布。正式既有資料的期限變更或清理先提供 dry-run 影響並獨立核准；本次僅設計／程式碼不授權直接刪正式資料。
