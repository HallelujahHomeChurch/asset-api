# HHC delivery entrypoint v1.1.0

Read the [canonical skill](https://github.com/HallelujahHomeChurch/hhc-planning/blob/9329942c91cc4d8d93104c666e2752024ee4e319/skills/hhc-delivery/SKILL.md) and [workflow](https://github.com/HallelujahHomeChurch/hhc-planning/blob/9329942c91cc4d8d93104c666e2752024ee4e319/workflow/v1/WORKFLOW.md) through authorized GitHub access before implementation. Both are pinned to `9329942c91cc4d8d93104c666e2752024ee4e319` for Mac, Windows and cloud. If private access fails, report the blocker; do not infer state, request new scopes or copy private planning content into public files.

Reuse the engineering issue/PR and verify latest Project/Feature/head/dependencies. The single coordinator acknowledges assignment/handoff; record run ID, environment, branch and HEAD. A stale assignee/comment/heartbeat/timeout never authorizes takeover. Nonconflicting read-only diagnosis may continue.

Keep accepted Feature scope and incremental improvements separate. Record CI, merge, package publication, deployment, flag activation and real acceptance independently. Closed duplicates/cancellations are not shipped. Incoming external requests require Ray triage and do not grant execution authority.

Progress authority: [private HHC all-product Project](https://github.com/orgs/HallelujahHomeChurch/projects/1). Read the current item/status, accepted scope and remaining acceptance; do not revive the old PENDING bootstrap. The Project uses manual evidence reconciliation: all built-in status/closure workflows are disabled and auto-archive is not enabled. If Project/private authority access fails, report the specific blocker and continue only independently authorized nonconflicting work. Never expand OAuth scopes implicitly. Keep public evidence generic/sanitized and private details in the private Feature. Preserve local rules and unrelated work; this rollout adds no product code, merge/deploy or full-suite CI.
