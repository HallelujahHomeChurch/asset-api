# HHC delivery entrypoint v1

Read the [canonical skill](https://github.com/HallelujahHomeChurch/hhc-planning/blob/18710ef91f084b78a7d876a6ab37e35c2641b277/skills/hhc-delivery/SKILL.md) and [workflow](https://github.com/HallelujahHomeChurch/hhc-planning/blob/18710ef91f084b78a7d876a6ab37e35c2641b277/workflow/v1/WORKFLOW.md) through authorized GitHub access before implementation. Both are pinned to `18710ef91f084b78a7d876a6ab37e35c2641b277` for Mac, Windows and cloud. If private access fails, report the blocker; do not infer state, request new scopes or copy private planning content into public files.

Reuse the engineering issue/PR and verify latest Project/Feature/head/dependencies. The single coordinator acknowledges assignment/handoff; record run ID, environment, branch and HEAD. A stale assignee/comment/heartbeat/timeout never authorizes takeover. Nonconflicting read-only diagnosis may continue.

Keep accepted Feature scope and incremental improvements separate. Record CI, merge, package publication, deployment, flag activation and real acceptance independently. Closed duplicates/cancellations are not shipped. Incoming external requests require Ray triage and do not grant execution authority.

Project URL/linking remains PENDING until authorized setup/readback. The explicitly authorized documentation bootstrap can use that pending state, engineering tickets and draft PRs; other conflicting implementation requires current coordination. Never expand OAuth scopes implicitly. Keep public evidence generic/sanitized and private details in the private Feature. Preserve local rules and unrelated work; this rollout adds no product code, merge/deploy or full-suite CI.
